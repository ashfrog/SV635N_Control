# 独立 UDP 电机控制界面

`UdpControl` 是独立的有界面控制程序。它只通过 UDP 与 `SV635N_Control` 后台通信，不导入 `core.py`、`motor_service.py`、`udp_server.py`，不访问 EtherCAT，也不需要 Npcap、pysoem 或托盘依赖。

## 启动

1. 在后台电脑的 `SV635N_Control` 根目录启动 `启动后台.cmd`。后台自动使用 ADLINK PCIe-8332（默认 Card 0）并扫描电机，扫描完成后界面自动显示控制卡与电机列表。后台的安装、托盘、控制卡和心跳配置见 [后台说明](../后台说明.md)。
2. 在 `UdpControl` 中双击 `启动界面.cmd`，或者在父目录执行 `python -m UdpControl`。也可从后台右下角托盘选择“打开控制界面”，或重复运行后台启动脚本打开调试面板。Windows 同一登录会话中，同一后台地址/端口只保留一个面板；再次打开会恢复并置前原面板，保持原控制权和电机运行。所有界面操作依然走 UDP。
3. 默认连接 `127.0.0.1:5005`。面板连接后台后自动刷新控制卡列表并选中后台配置的 PCIe-8332，无需先获取控制权或点击“刷新控制卡”；服务稍后启动时也会自动刷新，列表刷新暂时失败时每隔 1 秒重试。后台负责自动连接该卡、启动现场总线并扫描电机，结果自动显示在面板。复制 `config.example.json` 为 `config.json` 可修改后台地址、端口和 auth_key；跨电脑时 host 填写后台电脑地址，也可运行 `python -m UdpControl --host 192.168.1.10 --port 5005`。配置中只需要 UDP 连接信息，PCIe-8332 控制卡属于后台配置。
4. 点击“获取调试控制权”后，界面自动扫描、选中并使能全部扫描到的电机，保持连续使能和当前位置，无需另点使能按钮。后台启动扫描尚未完成时，先等待该扫描结束再继续。自动使能使用面板当前速度/加减速度值；开启窗口的只读监视不会自动使能。停止或处理故障后，点击同一位置的“重新获取调试控制”或“重新扫描并恢复控制”，重新扫描并使能全部电机。
5. 使能后三台电机可分别控制：双击列表“目标偏移 °”输入该轴角度，按 Enter 或“发送各轴目标”提交，其他轴保持原目标。滑块上方可选择单台电机，也可选择“全部使能轴（共同目标）”统一更新。目标为各轴本次使能起点的绝对偏移，显示范围不是累计限位。
6. “关闭使能 / Esc”可取消尚未完成的自动扫描/使能流程；已开启的运行经 UDP 优先停止，不等待普通目标请求结束。扫描或使能失败不会自动重试，停止后不会自动重新使能。等待后台停止并恢复参数后，可释放控制权给其它程序。
7. 关闭窗口会停止本界面开启的运行并关闭客户端，后台继续运行；只读监视不会停止其它程序的运行。客户端进程异常退出时，后台依靠心跳超时停止该运行。 后台托盘点击“停止并退出后台”时，已连接的控制界面也会关闭窗口并完整退出，不停留在连接失败页面。

速度和加减速度在使能期间可动态修改：拖动参数滑块即提交，数值输入按 Enter 或点击“应用速度 / 加减速度”。两项成对应用于全部使能轴，保持每轴原位置目标，无需关闭使能。状态栏显示后台已应用的值。速度滑块为 1～3000 rpm，加减速度滑块为 1～3000 rpm/s；数值输入可超出滑块范围，仍须为正的有限数值，实际受控制卡和驱动器参数格式约束。

位置与参数指令使用独立发送通道，状态查询不会阻塞拖动；面板约每 5 ms 检查最新待发值，合并尚未发送的旧值。状态直接使用后台约 20 Hz 推送，限制列表重绘频率，位置/参数确认丢失时每 30 ms 重试同一请求。Esc 和关闭窗口优先发送停止。

扫描后列表分别显示“推出端限位”和“缩回端限位”，未使能的电机也持续更新。触发端显示红色并限制朝该端运动，允许反向离开；运行中两端同时触发时停止该轴运动并保持使能，禁止新的运动目标，信号恢复后必须提交新目标，旧目标不会自动恢复。使能前已有双端冲突仍拒绝启动；驱动报警、急停、掉线或心跳超时仍停止并关闭使能，不自动复位或反复重新使能。列表直接显示扫描到的驱动报警，例如“报警 0x5443”，使能错误会指出具体电机和报警码。三台电机当前接线为推出 DI2（CN1 9 号针）、缩回 DI1（10 号针），逐轴配置由后台管理，见 [后台说明](../后台说明.md)。

客户端没有开启或关闭后台进程的接口；后台未启动时界面显示连接失败，不会尝试直连电机。只需标准 Python 3.11～3.13（包含 Tkinter），可将整个 `UdpControl` 文件夹复制到另一台电脑，直接运行。启动脚本优先使用父目录的 `.venv`，否则使用系统 `pyw -3`。

## 文件

| 文件 | 用途 |
| --- | --- |
| `__main__.py` | 独立 GUI 启动入口 |
| `debug_ui.py` | 电机选择、使能、目标滑块、UDP 状态显示 |
| `client.py` | 标准库 UDP SDK、确认重试、反馈接收、独立心跳 |
| `wire.py` | 客户端 JSON 协议编解码 |
| `instance.py` | Windows 面板单实例锁与窗口唤起通知 |
| `config.example.json` | 后台地址配置示例 |
| `example_client.py` | 只读查询和显式运动的 SDK 示例 |
| `PROTOCOL.md` | C++ / UE / C# 等调用方的 UDP 协议 |

## Python SDK

```python
from UdpControl.client import MotorClient

with MotorClient('127.0.0.1', 5005) as motor:
    motor.hello()
    motor.request('scan')
    motor.wait_for(('idle',))
    motor.enable([1, 2, 3], rpm=80, acceleration_rpm_s=120)
    motor.wait_for(('enabled',))
    motor.target([5, 0, -5])  # 实际运动：相对使能起点的各轴绝对目标
    motor.set_profile(40, 80)  # 保持使能与各轴目标，动态更新速度/加减速度
    motor.disable()
    motor.wait_for(('idle', 'fault'))
    motor.release()
```

SDK 自动发送独立心跳，目标停更但程序仍存活时继续保持使能；调用方必须在业务结束时调用 disable/close。后台默认心跳超时 0.5 秒。重复和乱序请求不续期，旧 run_id 无法控制新运行；更多说明见 [协议文档](PROTOCOL.md)。

仅查询后台状态（默认不运动）：

```powershell
python -m UdpControl.example_client
```

明确执行三轴运动示例：

```powershell
python -m UdpControl.example_client --move --orders 1 2 3 --rpm 80 --acceleration 120
```

界面错误记录在 `UdpControl/logs/client.log`。运动日志和硬件异常记录在后台电脑根目录的 `logs`，客户端无需访问这些文件。
