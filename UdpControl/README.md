# 独立 UDP 电机控制界面

网口后台每次启动后的首次“获取调试控制权”会寻找三轴上下限位、回退复测并返回两端中点，保存本次中位和软行程，无需手填编码器位置。标定阶段显示进度，滑块暂不可用，Esc 随时停止。连续寻位最高 60 rpm（本机 5 mm/s），退出限位和两次低速复测最高 6 rpm，确认两端后的回中最高 600 rpm；完成后恢复选择的正常速度，正常上限仍是 3000 rpm，滑块自由拖动。重置按钮仅清空所选轴记录，下次获取三轴控制重新标定；不立即运动。关闭自动标定时仍须手动提供完整安全软行程。触底、堵转后的真实驱动故障不自动复位。

网口直连电机角度调试的界面和后台速度上限均为 3000 rpm，启动保留选定速度，不再强制改为 5 rpm。角度滑块可以自由拖动；超过已知行程时，后台只约束电机执行终点，不把滑块还原成当前位置。限位显示“方向锁存”时，即使原始 DI 已变清，也只能反向退出；程序记住触发位置，防止穿过窄感应片后继续朝机械止挡运动。停车后正常重启仍保留位置记忆。传感器应覆盖整个超程区，软行程与停车余量需通过实测标定。

`UdpControl` 是独立的有界面控制程序。它只通过 UDP 与 `SV635N_Control` 后台通信，不导入 `core.py`、`motor_service.py`、`udp_server.py`，不访问 EtherCAT，也不需要 Npcap、pysoem 或托盘依赖。

## 启动

三撑杆高度调试使用“三点高度 · UE 模拟”页：后台配置平台后自动选中该页，1/2/3 号分别对应前左/前右/后中。高度单位为 mm，0 回到已标定初始位，正数向上推，负数向下拉。先确认三轴均在物理初始位并勾选确认，再获取控制；三个滑块/数字可分别调节，共同高度同时设定三轴，无需发送按钮。数字停输 350 ms、Enter 或失焦设定，拖动即时设定；界面持续发送完整三轴目标，模拟 UE 约 30 Hz 数据流。停止后需重新确认初始位，未提交编辑不会自动恢复。速度和加速度使用后台平台配置，角度调试页在平台配置下禁用。

没有完整实机标定时，该页保持不可控制。可运行项目 `SVServer/启动模拟服务.cmd`，再运行 `SVServer/打开模拟调试界面.cmd` 联调；模拟不会加载 APS DLL 或访问电机。已确认每转升降 5 mm，真实配置还需核对方向、中位及上下可用行程，见 [UE接入](../UE接入.md)。下面的角度和动态参数操作适用于普通电机模式。

固定中位的保存/返回独立于高度滑块：首次在角度页低速将三轴调到实际中位，关闭使能并等停稳，在高度页点“保存当前位置为固定初始位”。停止或服务重启后可点“低速返回固定初始位”（5 rpm / 10 rpm/s），返回后保持使能，Esc 停止；等三轴实际高度接近 0 后关闭使能，再确认中位并进入高度控制。后台保存原始轴位置到 `platform.reference.json`，保存操作不移动。若驱动器计数被清零、控制卡坐标重置、断电后计数不保留或换设备，必须重新建立中位，不能直接使用旧位置。普通角度页“回到使能起点”只返回本次使能开始处。

1. 在后台电脑的 `SV635N_Control` 根目录启动 `启动后台.cmd`。后台默认通过主板 Realtek 网口直连并扫描 SV635N，扫描完成后界面自动显示网口与电机列表。后台的安装、托盘、控制卡和心跳配置见 [后台说明](../后台说明.md)。
2. 在 `UdpControl` 中双击 `启动界面.cmd`，或者在父目录执行 `python -m UdpControl`。也可从后台右下角托盘选择“打开控制界面”，或重复运行后台启动脚本打开调试面板。Windows 同一登录会话中，同一后台地址/端口只保留一个面板；再次打开会恢复并置前原面板，保持原控制权和电机运行。所有界面操作依然走 UDP。
3. 默认连接 `127.0.0.1:5005`。面板连接后台后自动刷新网口列表并选中后台配置的主板网口，无需先获取控制权或点击“刷新网口”；服务稍后启动时也会自动刷新，列表刷新暂时失败时每隔 1 秒重试。后台负责连接所选网口并扫描电机，结果自动显示在面板。复制 `config.example.json` 为 `config.json` 可修改后台地址、端口和 auth_key；跨电脑时 host 填写后台电脑地址，也可运行 `python -m UdpControl --host 192.168.1.10 --port 5005`。配置中只需要 UDP 连接信息，EtherCAT 网口和可选 PCIe 控制卡属于后台配置。
4. 点击“获取调试控制权”后，界面自动扫描、选中全部电机。启用自动回中时，本次后台首次必须控制全部三轴，先完成寻两端、复测、回中，再按面板速度进入连续使能。同次后台后续获取控制保持当前位置；重启或清空记录后重测。只读监视不会自动使能，标定失败不会自动重试。
5. 使能后三台电机可分别控制：双击列表“目标偏移 °”输入该轴角度，停输 0.35 秒自动设定，也可按 Enter 或离开输入框立即设定，其他轴保持原目标。滑块上方可选择单台电机，也可选择“全部使能轴（共同目标）”统一更新，拖动即生效。目标为各轴本次使能起点的绝对偏移，显示范围不是累计限位。
6. “关闭使能 / Esc”可取消尚未完成的自动扫描/使能流程；已开启的运行经 UDP 优先停止，不等待普通目标请求结束。扫描或使能失败不会自动重试，停止后不会自动重新使能。等待后台停止并恢复参数后，可释放控制权给其它程序。
7. 关闭窗口会停止本界面开启的运行并关闭客户端，后台继续运行；只读监视不会停止其它程序的运行。客户端进程异常退出时，后台依靠心跳超时停止该运行。 后台托盘点击“停止并退出后台”时，已连接的控制界面也会关闭窗口并完整退出，不停留在连接失败页面。

速度和加减速度在使能期间可动态修改：拖动参数滑块即提交，数值停输 0.35 秒自动设定，也可按 Enter 或离开输入框立即设定。两项成对应用于全部使能轴，保持每轴原位置目标，无需关闭使能。未完成或无效的数字不提交；停止会取消尚未提交的编辑。状态栏显示后台已应用的值。速度滑块为 1～3000 rpm，加减速度滑块为 1～3000 rpm/s；数值输入可超出滑块范围，仍须为正的有限数值，实际受控制卡和驱动器参数格式约束。关闭界面使用标题栏关闭按钮。

位置与参数指令使用独立发送通道，状态查询不会阻塞拖动；面板约每 5 ms 检查最新待发值，合并尚未发送的旧值。状态直接使用后台约 20 Hz 推送，限制列表重绘频率，位置/参数确认丢失时每 30 ms 重试同一请求。Esc 和关闭窗口优先发送停止。“显示中心/跨度”只调整视图，切换 360/3600 等范围不改变目标和使能；重绘和程序同步滑块时禁用 Scale 回调并处理延后重绘，防止视图变化误发目标。

扫描后列表分别显示“推出端限位”和“缩回端限位”，未使能的电机也持续更新。触发端显示红色并限制朝该端运动；普通角度调试会暂停本次目标并保持使能，目标显示保留用户请求，可在同一次控制中直接提交反向目标离开，无需重新获取控制；运行中两端同时触发时暂停本次运动并保持使能，禁止新的运动目标，信号恢复后必须提交新目标，旧目标不会自动恢复。使能前已有双端冲突仍拒绝启动；有效驱动故障、急停、掉线或心跳超时仍停止并关闭使能，不自动复位或反复重新使能。普通警告继续显示，不单独中断控制。三台电机当前接线为推出 DI2（CN1 9 号针）、缩回 DI1（10 号针），逐轴配置由后台管理，见 [后台说明](../后台说明.md)。

列表下方的“重置所选限位记录”用于清除勾选轴的历史传感器触发位置，例如把上下传感器临时放在同一位置测试后留下的冲突。先关闭使能并等待停稳，再点击；手动软限位保留。若实际输入仍触发，会重新记录，不能用此按钮越过正在触发的硬限位。

“软限位设置”支持每轴启用和输入下限、上限，单位为电机角度 °，下限必须小于上限。固定零点计数跨使能和重启保存，与主界面每次使能起点不同；“当前位置为 0”只改变这份软限位的基准，不清零编码器。示例：在行程中间取 0，根据实测行程填入负下限和正上限，并留出停车距离。保存会清除这些轴旧的传感器位置记录，实际限位输入继续有效，不使能、不移动。读取或写入失败会显示原因。最高速度仍为 3000 rpm；滑块可超出软限位，后台只约束电机实际执行终点。

客户端没有开启或关闭后台进程的接口；后台未启动时界面显示连接失败，不会尝试直连电机。只需标准 Python 3.11～3.13（包含 Tkinter），可将整个 `UdpControl` 文件夹复制到另一台电脑，直接运行。启动脚本优先使用父目录的 `.venv`，否则使用系统 `pyw -3`。

## 文件

实机高度滑块灰色时，在“三点高度 · UE 模拟”页使用“配置 / 启用高度控制”：先关闭使能、保存真实机械中位，再填写三轴上下可用行程并核对传感器方向。后台保存并启用高度配置；随后勾选中位确认，重新获取控制，才能拖动高度滑块。正在角度运行时不能直接切换高度模式。配置保存不会使能或移动电机。

| 文件 | 用途 |
| --- | --- |
| `__main__.py` | 独立 GUI 启动入口 |
| `debug_ui.py` | 电机选择、使能、目标滑块、UDP 状态显示 |
| `client.py` | 标准库 UDP SDK、确认重试、反馈接收、独立心跳 |
| `wire.py` | 客户端 JSON 协议编解码 |
| `instance.py` | Windows 面板单实例锁与窗口唤起通知 |
| `config.example.json` | 后台地址配置示例 |
| `example_client.py` | 只读查询和显式运动的 SDK 示例 |
| `PROTOCOL.md` | C++ / UE / C# 等调用方的 UDP 协议 |

## Python SDK

```python
from UdpControl.client import MotorClient

with MotorClient('127.0.0.1', 5005) as motor:
    motor.hello()
    motor.request('scan')
    motor.wait_for(('idle',))
    motor.enable([1, 2, 3], rpm=80, acceleration_rpm_s=120)
    motor.wait_for(('enabled',))
    motor.target([5, 0, -5])  # 实际运动：相对使能起点的各轴绝对目标
    motor.set_profile(40, 80)  # 保持使能与各轴目标，动态更新速度/加减速度
    motor.disable()
    motor.wait_for(('idle', 'fault'))
    motor.release()
```

SDK 自动发送独立心跳，目标停更但程序仍存活时继续保持使能；调用方必须在业务结束时调用 disable/close。后台默认心跳超时 0.5 秒。重复和乱序请求不续期，旧 run_id 无法控制新运行；更多说明见 [协议文档](PROTOCOL.md)。

仅查询后台状态（默认不运动）：

```powershell
python -m UdpControl.example_client
```

明确执行三轴运动示例：

```powershell
python -m UdpControl.example_client --move --orders 1 2 3 --rpm 80 --acceleration 120
```

界面错误记录在 `UdpControl/logs/client.log`。运动日志和硬件异常记录在后台电脑根目录的 `logs`，客户端无需访问这些文件。
