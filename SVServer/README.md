# SVServer 便携后台（Windows x64）

双击 `SVServer.exe` 或 `启动服务.cmd` 即可启动后台，图标位于 Windows 右下角托盘。托盘可打开独立控制界面、停止全部电机、停止并退出后台。启动只扫描，不使能电机；重复启动会打开已有后台的控制界面。

`打开控制界面.cmd` 仅启动界面，不启动后台。也可执行 `SVServer.exe --client`。控制界面通过 UDP 连接服务，默认 `127.0.0.1:5005`。

本目录已包含 Python 和依赖库，运行不需要安装 Python 或复制项目源码。请复制**整个 SVServer 文件夹**，保留 `_internal/`；不可只复制 EXE。放在有写权限的目录，配置和日志保存在 EXE 旁边，不依赖当前工作目录。

## 网口与配置

默认 `backend: "ethercat"`，通过本机主板 Realtek Gaming 2.5GbE 网口直连 SV635N。适配器为 `\Device\NPF_{89B39964-A086-4A5D-BC55-D5804AE703C6}`。本机安装 Npcap 并启用 WinPcap API 兼容模式即可，pysoem 已随包提供；默认无需 ADLINK 驱动或 APS SDK。

主板网口 → 第一台 CN3 IN，第一台 CN4 OUT → 下一台 CN3 IN，依次串联，不接普通交换机。换电脑时修改 `adapter` 或在界面刷新网口后选择。`nic.extension_limits/retraction_limits` 按从 1 开始的链路位置配置，本机三轴为 DI2 防推出、DI1 防缩回；核对实际接线和驱动器功能。直连急停由实际驱动器/硬件回路处理。

如需原 PCIe-8332 模式，显式设置 `backend: "aps"`、`adapter: "PCIe-8332:0"` 和 `aps` 配置，并安装 ADLINK 驱动及 APS SDK；详见项目 `后台说明.md`。切换后端后需重新保存实际固定中位。

`backend.config.json` 是本机实际配置，首次构建从项目现有配置复制；重新打包不会覆盖本目录已有配置和日志。换电脑时必须按实际硬件调整，示例中的轴号、传感器和急停配置不表示新机器的实测值。平台机构参数见项目 `UE接入.md`；`backend.platform.example.json` 采用已确认的撑杆轴线中心距：前方 670 mm、两斜边各 730 mm，以三点重心为原点，前左/前右/后中对应 1/2/3 号电机，实机扫描应核对与链路 order 一致。已确认 1:1 皮带传动、电机两圈升降 10 mm，三轴 `mm_per_rev=5`。方向及行程仍为模拟假设，默认关闭实机平台模式。

后台记录在 `logs/service.log`，客户端记录在 `logs/client.log`。关闭客户端会停止该客户端的运行，后台继续运行；退出真实后台请使用托盘“停止并退出后台”，等待停止/关闭使能及参数恢复完成。

本程序是托盘常驻进程，未注册为 Windows 系统服务，未修改开机启动。

网口直连未标定固定中位和实测软行程时，最高 5 rpm，后台拒绝超速使能和调速。限位首次触发后记住原生编码器边界，穿过窄感应片导致电平变清也不能继续朝外运动，允许反向退出；停车后保存 `logs/nic-limit-memory.json`，正常重启保留。已标定模式按机构速度、软行程和制动距离提前停车。运行中临时设置 H02.07=4、605D=2，使用独立的 6085 停车减速度并保持位置锁定，退出后恢复原参数。停车余量未知时不要恢复高速；传感器须覆盖整个超程区并留出经过实测的停车空间。

网口直连的普通警告和内部限幅不再单独中断控制；`0x5443/0x5444` 超程继续限制相应方向。普通角度调试到达限位后暂停并保持使能，直接提交反向目标即可离开，无需重新获取控制；旧目标丢弃，平台高度模式仍全轴停止。残留 `0x0E08` 通信故障可在点击“重新获取调试控制”后、总线已恢复且全部轴未使能时尝试一次复位；有效故障、急停或持续断联仍会停止。

## 无硬件模拟联调

双击 `启动模拟服务.cmd`，再双击 `打开模拟调试界面.cmd`。也可执行 `SVServer.exe --simulate --port 5006` 与 `SVServer.exe --client --port 5006`。此模式不加载 APS DLL、不访问电机，使用模拟平台配置；UE 使用端口 5006 和标定名 `simulation-only-v1`。模拟进程无托盘；只在确认模拟模式时可通过任务管理器结束它。

调试界面增加“三点高度 · UE 模拟”页，前左 1、前右 2、后中 3。输入为相对标定初始位的毫米高度，0 回初始位、正数上推、负数下拉；三个滑块/数字分别调节，共同高度可同时设定，另可一键将三轴目标设为 0。首次先保存固定初始位，勾选已确认初始位后获取控制，界面持续以约 30 Hz 发送与 UE 相同的完整高度数据，无需额外发送按钮。数字停输 350 ms、Enter 或失焦设定。真实模式需要完成毫米标定，停止后重新确认物理初始位。

首次保存固定中位：在角度调试页低速将三根撑杆调到实际中位，点“关闭使能 / Esc”，等停稳后在高度页点“保存当前位置为固定初始位”。以后在停止状态点“低速返回固定初始位”，确认位置计数未清零且路径可通行，三轴以 5 rpm 返回；返回后保持使能，Esc 可停止。实机位置存放 `platform.reference.json`，模拟存放 `platform.simulated.reference.json`，重新打包保留它们。固定中位保存/返回可以在平台尚未完成毫米行程标定时使用，但高度滑块仍禁用。断电、位置清零或坐标重置后须重新标定，保存文件不能代替驱动器机械回零。

高度页右上角的“配置 / 启用高度控制”提供实机标定入口：先关闭使能、保存实际固定中位，再填写三杆从中位向上/向下的可用行程，并确认编号及两端传感器对应方向。已确认本项目三杆上下各 50 mm，当前本机配置预填 ±50 mm。保存后配置立即生效并持久化，不移动电机；勾选中位确认并重新获取控制后，三个高度滑块才启用。原配置备份为 `backend.config.json.before-platform.bak`，其它控制卡/网络配置保留。已使能时点击设置会提示先停止，不直接切换运动模式。整体升降取三杆共同可用行程，本项目为 ±50 mm；首次倾角限制 ±3°、速度 5 mm/s；各轴行程和平台整体限制同时检查。

## 从源码重新构建

在完整项目内双击 `重新打包.cmd`，或者：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe build_svserver.py
```

构建输出为 `SVServer/SVServer.exe` 和 `_internal/`，构建中间文件位于 `.build/svserver/`。发布包未进行代码签名。

重新打包前退出正在使用本目录的 EXE。可运行 `python packaging/smoke_test.py` 验证迁移运行、模拟平台协议、托盘入口和独立客户端；验证不会访问真实 APS 硬件，结果写入 `verification.json`。
