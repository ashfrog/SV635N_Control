# SV635N_Control

网口后台每次启动后，首次点击“获取调试控制权”会自动寻找三轴下限、回退复测、寻找上限、回退复测，再移动到各轴两端中点。中点作为本次零位，自动保存向内留余量的软上下界，无需手填编码器位置。后台启动扫描或仅打开只读窗口不会运动。连续寻位最高 60 rpm（本机 5 mm/s）；退出限位和复测最高 6 rpm，确认两端后的回中最高 600 rpm。完成后恢复面板选择的正常速度，正常上限仍为 3000 rpm，滑块不受限。Esc、断联、驱动有效故障、双端同时触发、搜索超距或装平台时三轴相对进度差超过 2 mm 均中止，不自动重试。

本机读到三轴 H02.01=0（增量模式），不能把断电前的计数直接当成本次机械坐标；程序不改编码器模式、不清零编码器。自动标定用 `auto_center` 配置，每转 5 mm；`nominal_travel_mm=100` 对应最大搜索 120 mm，有效实测全行程至少 10 mm，不要求传感器间距恰为 100 mm。必须具备两端有效 P/N-OT。退出限位和复测每步最多 0.02 mm，信号释放后再退 0.5 mm，总回退距离最多 5 mm；停车确认后才反向，复测差不得超过 0.1 mm。连续寻位使用有固定终点的 PP 轨迹，缺少传感器时不会延长搜索；限位 Halt 减速度至少 3000 rpm/s。先确认传感器位置及停车余量；软件标定不能弥补错误接线或机械止挡前没有停车空间。

当前实机为未安装平台的三根独立推杆，实际配置 `coupled_axes:false` 用于分别标定各自的临时限位。默认示例为 `true`；启用平台配置后后台始终启用同步偏差保护，不能沿用独立推杆方式遍历不同端点。平台首次获取控制也可自动寻位，完成后直接进入高度控制；无需先绕到角度模式。平台配置窗口优先填入本次自动测得的安全上下行程。正式安装后仍须核对撑杆编号、水平中位和限位器位置。

回中停稳位置允许 `center_tolerance_mm:1`（1 mm）的误差，不因微小偏差中断流程。用实际停稳位置作本次零点时会同步换算软限位，保持原始编码器端点不变；此容差不会放宽限位边界。故障停止后分别保留 PDO 关闭确认 `all_disabled`、逐轴 SDO 关闭确认 `all_disabled_sdo` 和 `all_preop`，不能把缺少反馈视为已安全关闭。链路计数在停止后、重新扫描前读取，因为 SOEM 扫描会重置 CRC 计数。

连续角度运动仍须完整有效的软上下边界；关闭自动标定时需手动设置，缺少时只保持使能并提示。触限后停车目标固定，确认至少 50 ms 编码器稳定且驱动报告到位后，才执行新反向目标；旧目标不恢复。硬限位按垂直轴建议设置 H02.07=1（零速停机、位置锁定），软件提前停车仍用 605D=2/6085。

显示中心/跨度只调整滑块视图：切换 360/3600 或缩小范围均保留目标和使能，不发送运动指令。网口通信复位会等待错误码清零后的故障状态位完成清除，不再把该短暂过渡误报为 `0x0000` 故障；运行中的有效故障仍停车。出现 EE08/WKC 掉线时，先从托盘停止并退出后台，再运行“优化电机网口（管理员）.cmd”并允许 Windows 管理员提示。该入口只修改已配置的电机专用网口，核对全部轴未使能、备份原设置后关闭中断合并和支持的节能选项，再验证链路；不发送使能/运动指令。完成后重新启动后台。

限位位置可在电机列表下方管理：停机后勾选电机，点“重置所选限位记录”仅清空该轴已学习的边界及自动生成的软限位，不使能、不移动；下次获取全部三轴控制会重新标定。人工设置的软限位保留。“软限位设置”保留手动调整功能，单位为相对固定零点的电机角度 °。记录保存在 `logs/nic-limit-memory.json`，首次修改前自动备份，实际限位输入始终有效。

SV635N 主板网口直连 EtherCAT 电机后台（Python 源码版），通过 UDP 接收单轴/多轴连续运动目标，提供托盘入口和独立控制客户端。

便携 EXE 发布目录为 [SVServer](SVServer/README.md)：双击 `SVServer/SVServer.exe` 或 `SVServer/启动服务.cmd` 启动，复制整个目录即可部署，无需安装 Python。本机需安装 Npcap（启用 WinPcap API 兼容模式）；默认使用主板 Realtek Gaming 2.5GbE 网口。构建方法：安装 `requirements-build.txt` 后运行 `python build_svserver.py`；托盘和客户端各自运行在独立进程中。

双击根目录的 `启动源码.cmd` 或 `启动后台.cmd` 启动托盘后台，控制界面由 `UdpControl/启动界面.cmd` 或托盘“打开控制界面”启动。运行环境使用本项目的 `.venv`，不依赖临时工作目录。

首次使用或更换电脑时，安装 Python 3.11～3.13 x64 和 Npcap（启用 WinPcap API 兼容模式），然后在项目根目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

示例使用 Python 3.12；使用其他受支持版本时，请相应修改版本号。

文件：`backend.py` 为后台入口，`motor_service.py` / `udp_server.py` 为服务与协议，`nic_backend.py` / `core.py` / `continuous_control.py` 为网口直连控制核心，`aps_backend.py` 保留可选 PCIe-8332 后端，`control_common.py` 为共享类型/目标槽，`UdpControl` 为独立 UDP 界面与 SDK。`app.py` 和 `cli.py` 保留独立直连调试入口，依赖已包含在 `requirements.txt`。接线与旧调试操作见 [使用说明.md](使用说明.md)。

常驻 UDP 后台在根目录实现，见 [后台说明](后台说明.md)：双击 `安装后台依赖.cmd` 后运行根目录 `启动后台.cmd`，或执行 `python backend.py --headless`。独立控制界面在 [UdpControl](UdpControl/README.md)，使用 `UdpControl/启动界面.cmd` 或 `python -m UdpControl`，也可由后台右下角托盘打开。界面只通过 UDP 控制后台，可复制到其它电脑使用，无需电机驱动依赖。Python SDK 为 `UdpControl.client.MotorClient`。

电机调试模式：点击“获取调试控制权”后自动扫描并选中全部电机；启用自动回中时首次必须是三轴，按上文完成标定后进入连续使能，无需额外使能按钮。同一次后台运行中，后续重新获取控制保持当前位置，不重复寻限位；清空记录或重新启动后台才要求重测。默认正常速度为 60 rpm / 120 rpm/s，最高 3000 rpm。使能期间可更新速度、加减速度及每轴目标；新目标覆盖未下发的旧目标。实际操作见 [客户端说明](UdpControl/README.md)。

网口直连的普通警告和内部限幅不再单独中断控制；`0x5443/0x5444` 超程继续限制相应方向。普通角度调试到达限位后暂停并保持使能，滑块和用户目标保持原值，直接提交反向目标即可离开，无需重新获取控制；旧运动丢弃，平台高度模式仍全轴停止。残留 `0x0E08` 通信故障可在点击“重新获取调试控制”后、总线已恢复且全部轴未使能时尝试一次复位；有效故障、急停或持续断联仍会停止。

网口直连电机角度调试最高 **3000 rpm**（界面与 UDP 一致），不再因未标定限制为 5 rpm，启动仍使用界面选择的速度。三点高度模式保留机构速度上限，已标定的位置软边界及 `v²/(2a)+v·T+余量` 提前停车。硬限位首次触发的编码器位置保留为方向边界，穿过感应片后信号消失也不解除危险方向；反向退回边界内才能解除锁存，记录的边界仍阻止再越过。停车后位置记忆保存到 `logs/nic-limit-memory.json`，正常重启保留；更换机构、编码器清零或坐标变化必须重新核对标定。限位片应在整个超程区持续有效，并留出实测最坏停车距离；程序保护不能补偿传感器之后没有制动空间。

三竖向撑杆平台：UE 通过 UDP v1 提交 `[前左1号, 前右2号, 后中3号]` 三个相对标定初始位的高度（mm），0 回初始位，正数上推，负数下拉。`platform_motion.py` 提供毫米/电机角度转换、行程与平台姿态范围校验、共同进度插值、速度与加速度约束、独立输入超时、跟随误差与全轴限位停止，兼容旧姿态输入。调试界面的“三点高度 · UE 模拟”页可分别或共同调节三轴，并持续发送约 30 Hz 高度流。UE 接口为 `SetPlatformHeights`，见 [UE 接入与实机边界](UE接入.md)。真实平台默认未启用；`backend.platform.example.json` 采用已确认的 670/730/730 mm 安装结构及每转 5 mm，但方向和行程仍为模拟假设，必须完成实测标定。配置平台后默认禁止直接电机调试，防止绕过平台约束。可先运行 `python simulated_backend.py`（仅模拟，端口 5006），通过界面、UE 或 Python SDK 验证完整流程。

后台默认 `backend: "ethercat"`，通过本机 Realtek Gaming 2.5GbE 网口直连 SV635N，启动只扫描、不使能。接线：主板网口 → 第一台 CN3 IN，CN4 OUT → 下一台 CN3 IN，不经普通交换机。已配置网口为 `\Device\NPF_{89B39964-A086-4A5D-BC55-D5804AE703C6}`；换电脑时在面板刷新网口后选择，或修改 `adapter`。不需要 APS SDK、MCPro2 或 ENI。原 PCIe 后端需显式设置 `backend: "aps"`、`adapter: "PCIe-8332:0"` 及对应 `aps` 配置。`platform_control.py` / `ue_demo.py` 保留旧三轴协议，与当前 UE 组件不兼容。完整无硬件回归：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
```

`.venv/`、`logs/`、`settings.json` 和 Python 缓存均为本机运行数据，已加入 Git 忽略规则。`logs/` 和 `settings.json` 会在使用时生成。
